# Вакф · Салихин

Двуязычный (тоҷикӣ / русский) информационный сайт о вакфе для Salihen.tj.
Next.js 15 (App Router) + TypeScript + Tailwind CSS. Полностью статическая
сборка (SSG) — хостится как обычный набор файлов, отдельный сервер не нужен.

## Быстрый старт

```bash
npm install
npm run dev        # http://localhost:3000/tj и /ru
```

Продакшен-сборка:

```bash
npm run build
npm start           # либо `next export`-подобный статический хостинг —
                     # проект полностью статический, все страницы пререндерятся
```

Проверка типов: `npm run typecheck`.

## Публикация на GitHub Pages (бесплатно, без Vercel)

Сайт полностью статический, поэтому GitHub Pages подходит без каких-либо
серверных функций. Всё уже настроено:

1. В репозитории на GitHub → **Settings → Pages → Source** выберите
   **"GitHub Actions"** (один раз).
2. Сделайте `git push` в ветку `main` — workflow `.github/workflows/deploy-pages.yml`
   сам соберёт сайт (`STATIC_EXPORT=true`) и опубликует папку `out/`.
3. Через 1–2 минуты ссылка появится в репозитории на вкладке **Actions** (в
   деталях последнего запуска, шаг *deploy*) — обычно это
   `https://ваш-логин.github.io/название-репозитория/`.

По умолчанию workflow сам подставляет `NEXT_PUBLIC_BASE_PATH` равным имени
репозитория (нужно для адресов вида `.../название-репозитория/`). Если позже
подключите свой домен (**Settings → Pages → Custom domain**, например
`vaqf.saliheen.tj`) — откройте `.github/workflows/deploy-pages.yml` и замените
строку `NEXT_PUBLIC_BASE_PATH: /${{ github.event.repository.name }}` на
`NEXT_PUBLIC_BASE_PATH: ''`, иначе пути будут вести мимо.

Собрать статический экспорт вручную (проверить локально):
```bash
STATIC_EXPORT=true NEXT_PUBLIC_BASE_PATH=/название-репозитория npm run build
# результат — папка out/, её содержимое и есть готовый сайт
```

## Структура

```
src/
  app/
    [locale]/          # /tj и /ru — единственный роут, языком управляет segment
      layout.tsx        # шрифты, <html lang>, метаданные, OG/Twitter, hreflang
      page.tsx           # сборка страницы из компонентов + JSON-LD
    not-found.tsx        # общий двуязычный 404
    robots.ts / sitemap.ts
    globals.css          # ЦВЕТА САЙТА — см. блок BRAND TOKENS в начале файла
  components/             # По одному файлу на секцию (Hero, About, Sharia, Legal, …)
  content/
    types.ts              # Единый интерфейс Content — форма данных для языка
    ru.ts / tg.ts          # Все тексты сайта, ОБА языка порознь
    sources.ts             # Реестр источников (Коран/хадисы/фикх/законы) — сноски [n]
    index.ts               # getContent(lang) — точка подключения CMS в будущем
  config/
    site.ts                # Название организации, контакты, соцсети, логотип
    projects.ts             # Проекты Салихин (с сайта) + направления Вакфа (пока пусто)
    transparency.ts          # Ссылки на отчётность + метрики (пока пусто)
    payment.ts                # Реквизиты для раздела «Поддержать»
  i18n/config.ts                # tg↔ru, /tj↔/ru segment-маппинг
```

## Принцип наполнения контента

**Ничего не выдумано.** Каждый шариатский или правовой тезис в `ru.ts`/`tg.ts`
снабжён `cite: [...]` — ссылкой на конкретный источник в `sources.ts`, который
был реально прочитан при подготовке текста. Если для какого-то раздела
подтверждённых данных не было (направления именно Вакфа, метрики, Устав) —
вместо выдумки на сайте честно показывается плашка «будет опубликовано».
Это осознанное архитектурное решение, а не недоделка — так и должно остаться
при дальнейшем редактировании.

## Что нужно донастроить перед полным запуском

1. **Устав организации** — сейчас `legal.docs.charter` в `Legal.tsx` показывает
   бейдж «Документ будет опубликован» (ссылки на файл в `config/transparency.ts`
   → `charterUrl` нет). Как только Устав появится в PDF — положите файл в
   `public/` и укажите путь в `charterUrl`.
2. **Направления именно Вакфа** (`config/projects.ts` → `vaqfDirections`) —
   сейчас пустой массив, поэтому в разделе «Почему вакф важен» показывается
   честная плашка-заглушка. Заполните массив, когда организация утвердит
   конкретные направления — плашка сама исчезнет и покажется сетка карточек.
3. **Метрики прозрачности** (`config/transparency.ts` → `metrics`) — аналогично,
   пустой массив → плашки «Данные готовятся». Заполните реальными цифрами,
   когда они появятся.
4. **Цвета и шрифты бренда** — палитра в `globals.css` (блок `BRAND TOKENS`
   в самом начале файла) сейчас авторская, не снята с официального сайта
   (его фирменный стиль недоступен для точного считывания). Поменять — значит
   отредактировать 12 CSS-переменных в одном месте, всё остальное подтянется
   само.
5. **Логотип** — сейчас используется файл `public/logo.png` (тот, что вы
   прислали). Если появится вариант в лучшем разрешении — просто замените
   этот файл тем же именем.
6. **`NEXT_PUBLIC_SITE_URL`** — скопируйте `.env.example` в `.env.local` и
   укажите реальный адрес, на котором сайт будет жить (влияет на OG-картинки,
   sitemap, canonical-ссылки).
7. **OG-картинки** — `layout.tsx` ссылается на `/og/og-tg.png` и `/og/og-ru.png`
   (1200×630) для превью в соцсетях; сейчас этих файлов нет в `public/og/` —
   добавьте, когда будет дизайн-картинка для шаринга.

## Платёжные реквизиты (раздел «Поддержать»)

Все реквизиты в `src/config/payment.ts` — из документов, которые вы прислали:
QR (скриншот виджета сайта), Alif Bank (TJS / USD / RUB) и Sberbank (RUB).
Названия банков и адреса в реквизитах **намеренно не переводятся** — это
платёжные данные, и точность важнее единообразия языка сайта. Если банк
пришлёт новые реквизиты или добавится способ оплаты — редактируется только
этот один файл.

## Источники (раздел «Источники»)

`src/content/sources.ts` — реестр из документов, которые реально были открыты
при подготовке текста: два аята Корана, несколько хадисов (Бухари, Муслим,
Насаи), классический фикх (Мугния, IslamQA, AAOIFI, решения Академии фикха
ОИС), Гражданский кодекс РТ и Закон РТ «О благотворительной деятельности».
Если в будущем добавляете новый тезис — сначала добавьте источник сюда,
потом ссылайтесь на его `id` через `cite`.
